<p>团队里换人是常事，麻烦的是账号环境跟着人走。这次做了一组对照：同样 8 个账号，一组交接时只留"账号密码加一句走某条线路"，另一组留了完整环境台账，记下出口 IP、ASN、运营商归属和常用登录时段。两组各交接两次，统计接手人从拿到账号到能正常对话花了多久、中间触发了几次额外验证。差距比预想的大，也顺带回答了第一次注册的人最担心的那件事：环境到底干不干净。下面把实验设计、记录字段和结论拆开讲。</p>

<h2>一、把"交接顺不顺"做成一组可复现的对照</h2>
<p>不做对照，讨论交接就只能靠感觉。有人觉得"给个密码不就行了"，也有人坚持要写三页文档。中间差在哪里，只有把两组放在同一批账号上跑一遍才看得清。</p>
<h3>分组方式</h3>
<p>取 8 个注册满两个月、日常用于对话和文档整理的账号，按注册时间两两配对，一半进 A 组，一半进 B 组，尽量减少账号年龄带来的偏差。A 组的交接材料是一张便签：账号、密码、备用邮箱、以及"走香港那条线"。B 组则给一份台账，字段见第三节。</p>
<h3>变量只留一个</h3>
<p>两组都用同一家供应商的原生家宽出口，同一个客户端版本，同一个登录时段窗口（上午 9 点到 11 点）。唯一变化的是交接材料的完整度。出口类型、设备、时段全部锁死，这样结果才好归因。</p>
<h3>怎么算"交接完成"</h3>
<p>接手人能独立完成一次登录、打开一个历史会话、发一条消息并拿到回复，且过程中没有出现需要人工确认的拦截页，记为完成。出现验证页就单独计次，不并入完成时间，避免两个指标混在一起看不清。</p>

<h2>二、A 组与 B 组的差别落在出口来源上</h2>

<p>A 组的问题在第二次交接时集中暴露。第一位接手人凭"香港那条线"自己找了一条机房段，登录后台显示的地区没错，但地址段属于数据中心，第二次交接时新同事又换了一条，两条记录的 ASN 完全不同。账号本身没被封，可每次交接都像重新开一个新环境。</p>
<h3>机房段与家宽段的记录差异</h3>
<p>用 <code>curl ipinfo.io</code> 或 <code>curl ip.sb</code> 查出口，机房段通常能看到 ASN 归属是云服务商或 IDC，org 字段写着 Hosting、Cloud、DataCenter 之类；原生家宽出口的 org 是当地电信、有线电视或光纤运营商，rDNS 里常带 dynamic、ppp、broadband 字样。两类地址在查询结果上就能分开，不需要靠猜。</p>
<h3>第一次注册的人担心什么</h3>
<p>多数人担心的是"前面用过的人把这条线用脏了"。这个担心有解：注册前把出口查一遍，看 ASN 是否为 ISP、rDNS 是否像家庭宽带、这条出口近 7 天是否被多个账号使用过。三项都过关，环境就算清爽。反过来，如果出口是共享机房段、一天内换过好几次 IP，那确实不适合拿来注册。</p>

<h3>更新频率</h3>
<p>换出口、换设备、改密码、续费，这四个动作发生时就更新，别攒到交接前补。攒着补的结果通常是漏项，而漏的那一项往往正是接手人最需要的。</p>

<h3>数字怎么读</h3>
<p>同一组内，出口从机房段换成家宽段，耗时从 95 分钟降到 40 分钟；组间差在第一次交接时最明显，因为 A 组还要先搞清楚"到底该走哪条线"。第二次 A 组有了一次经验，差距收窄，但仍没追平，说明台账本身还在起作用。</p>
<h3>成本折算</h3>
<p>按每小时 80 元人力估算，一次交接省 70 分钟约合 90 元。原生家宽出口单条月费区间大致 80 至 200 元，双 ISP 备份另加一条，一年多花的钱大概相当于十几次交接省下的工时（仅供参考）。交接频率越高，这笔账越划算。</p>

<h2>五、从这组数据里能带走的三条结论</h2>
<h3>结论一：记录比记忆可靠</h3>
<p>人走了，记忆就没了。五列台账写在共享文档里，谁接手都能复现。这不是流程洁癖，是把隐性知识变成可查的东西。</p>
<h3>结论二：出口类型决定了"像不像同一个人"</h3>
<p>机房段换来换去，ASN 一直在变，等于每次都在告诉平台"换了个人在登录"。原生家宽固定下来，ASN 和运营商稳定，跨设备交接时更容易被当作同一用户的正常换机。</p>
<h3>结论三：第一次注册的环境要单独验</h3>
<p>新号开出来之前花两分钟查出口，比开出来之后补救便宜得多。查 ASN、查 rDNS、查这条线近期有没有被多账号共用，三项都过再注册。</p>

<h2>常见问答</h2>
<h3>交接时能不能直接让同事用自己的网络登录？</h3>
<p>答：技术上可以，但地区、ASN、运营商三项会同时变化，等于一次三重变更。稳妥做法是先让同事接入同一条出口再登录，把变量减少到一个，出问题时也好定位。</p>
<h3>台账要记多细才够用？</h3>
<p>答：能回答三个问题就够：这条线是哪一类地址、上次是谁在用、下次该在什么时段登。五列已经覆盖，再细就是负担，反而没人愿意填。</p>
<h3>出口 IP 变了但 ASN 没变，要不要紧？</h3>
<p>答：家宽出口本来就常有地址漂移，同一 ASN 内的小幅变化通常不影响。要紧的是 ASN 和地区同时变，那才需要提前在台账里标注并告知接手人。</p>
<h3>第一次注册用共享出口行不行？</h3>
<p>答：不建议。共享出口的近期使用记录不可查，无法判断是否已被大量账号用过。一号一环境的做法虽然成本高一点，但把不确定性挡在门外，长期看更省心。</p>
